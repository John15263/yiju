# 整句试写：接着当前草稿往下提示

在“整句试写”中，提示全自动，没有提示按钮（“更多 → 练习记录与设置”里的“写的时候一停顿，就自动给一句提示”，默认开启，与短语默写共用，记在本浏览器）：进入整句、框还空着时给开头思路；停顿至少 1 秒后按最新草稿给第 1 级思路；思路出来后 10 秒草稿和光标都没动，就从同一份结果里展示下一个词（第 2 级，不再调用模型）。一小段表达和参考续写不会自动出现，Command + [ 仍可手动逐级要。进入整句时页面往往还在处理打开它的那条命令，此时不能排队；忙完后会补排一次，空框也能等到第一条提示（2026-09-23 修复：之前要先打字才会有提示）。连续自动请求至少间隔 1.5 秒（2026-09-27 起；以前是 1.5 秒和 2.5 秒），同一个页面只保留一个生成请求进行中。每条展示过的提示都留在输入框下方的列表里（来自 `writing_hint` 事件，带 `window_start`），最新的在最上面，旧的不会被替换掉；沿参考写着停下时，本地提示直接说出下一个词；停顿后以最新草稿和光标位置请求。主动求助不等待输入停顿。中文/日文输入法组合期间保留提示、不请求，选字结束后重新计时。思路和说明的语言由 `hint_language` 决定（`target` 为正在学的语言、非常简单的说法，`zh` 为中文，默认中文；网页默认 `target`），单词、短语和续写始终是目标语；本地即时提示的固定句也跟着切换，缓存按语言分开。展示出来的提示同时会被念出来，规则同短语提示（见 [短语练习](phrases.md)）。

- 沿着已有参考写到词边界时（包括空白草稿），由本地后端立即计算下一词、短语和续写，不调用 Gemini；结果仍要用户求助后才显示。
- 使用自己的不同措辞、在词中或句中编辑时，由 Gemini 依据原意、完整草稿、光标左右文字以及整段中文摘要准备提示，不要求逐字贴合参考。
- 求助阶梯固定从中文思路开始：第一次 Command + [ 给中文思路，之后依次是单词、短语、参考续写。草稿或光标变化后阶梯回到中文思路，旧结果不展示到新位置。提示独立展示，不插入或覆盖用户输入。
- 已经写完整时建议提交；需要局部调整时说明改哪里。Gemini 是候选帮助，最终检查仍在用户按 Command / Ctrl + Enter 提交以后进行。

Gemini 调用会发送当前单句原意、参考、草稿及光标两侧文字；成段练习附中文摘要、本句作用和衔接，不发送全部聊天或其他答案。提示请求的结果在进程内最多缓存 64 个输入快照，同快照并发合并。失败保留草稿，内容未变化时不自动重试，按快捷键可主动重试。服务重启不重放提示调用。

`POST /api/sentence/writing-help` 接受 `{round_id, window_start, draft, caret, retry?}`，caret 为 textarea 使用的 UTF-16 索引。只允许当前整句试写窗口，结果为 `{hint_id, status, meaning, word, phrase, continuation, note, provider, model}`。调用固定提示词 `studio/prompts/writing-help.txt`，不接收客户端自定义 prompt、模型、URL 或密钥。草稿最多 4000 字符。

页面在展示前通过 `POST /api/sentence/writing-help/seen` 提交 `{round_id, window_start, hint_id, level}`，记录本次草稿、光标、提示来源、展示的具体文字和支持级别；同提示同级别去重。`writing_hint` 支持事件随真实提交保存，模型提示不会伪装成用户回答。中文思路对应级别 0，词/短语/续写分别对应 1/2/3。使用帮助不扣分。

已经显示的提示保留到替换时；编辑后才返回的过期结果不会展示，也不会当作新草稿的提示使用。换句、重新试写、暂停或提交会清空提示，不应用旧窗口结果。提交等已启动的帮助记录落盘，不等待仍在生成的提示；输入框原文独立保存在浏览器，提交到后端时原样保存。网页的段落参考、固定支架和动态提示都属于帮助，不据一次完成推断长期掌握。
