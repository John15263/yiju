# 短语 → 整句 → 下一句

## 每块先学，再默写

短语阶段里每一块分两步，记在 `phrases.step`：

| 步骤 | 屏幕 | 陪练（⌘ ]） | 离开 |
|---|---|---|---|
| `learn` | 这一块的中文意思、外语写法和结构提示 | 进入时自动开始（可在设置里关掉），讲解提示词，只拿到**这一块**的外语写法；接通后直接开讲：不先念整块，把这一块切成词组、按顺序逐个讲意思，全部讲完再讲语法点，然后等提问；不让他跟读、复述或造句 | ⌘ ↵ / “开始默写”：`POST /api/sentence/phrases/write`，外语从页面上移除，学习对话随之结束 |
| `write` | 只有中文意思和输入框 | 试写提示词，拿不到参考 | 检查通过后进入下一块的 `learn` |

学习记录挂在每块的 `inputs[i].learn` 上（`sessions`、`seconds`、`skipped`、`started_at`、`finished_at`）。离开学习时按**实际发生过什么**结算：一次对话都没有就记 `skipped: true`；对话的关闭晚于点击“开始默写”时，关闭时再补记，并把 `skipped` 改回 false。`learn` 步骤里检查、提示、参考后继续都会被拒绝（409）。

学过或跳过的块（`finished_at` 已有）在重练（新一轮 run 或 `repeat`）时直接进入 `write`。离开短语阶段去写整句不会结算一块还开着的学习，回来时仍停在这一块的学习。每次整句 attempt 的 `learned` 为 `{ sessions, seconds, studied, chunks, skipped }`：`studied` 是真的聊过的块数，`skipped` 表示一块都没学。

刚按 ⌘ ↵ 进入下一块时，800 毫秒内的第二次 ⌘ ↵ 会被忽略，免得连按把下一块的学习跳过去。在这项功能之前保存、没有 `step` 的进行中短语按 `write` 处理。

默认入口用短语试写替代填空。Gemini 在整理段落时同时给每句准备按意义划分的表达块，通常 2–5 块，最长 8 块，极短句允许 1 块。每块包含中文意思、一个参考片段和两级预备提示（结构/搭配、开头线索）。各块按序完整覆盖整句参考，不按固定词数或单个假名切分。

短语判定由 Gemini 单层完成（`PHRASE_GATE=gemini`，默认）：

| 情况 | 行为 |
|---|---|
| 与准备好的片段完全一致 | 本地精确匹配，秒过，不调用任何模型 |
| 其它 | 一次 `GEMINI_MODEL` 调用（和整句点评同一个模型，2026-09-23 起不再用 flash-lite；3.8-flash 先思考再回答，约 2.5–5 秒，超时 `GEMINI_NOTE_TIMEOUT_MS` 默认 20 秒）：`ok` 判为通过，`adjust` 留在本块，两种都附带可读的理由与最小改动后的写法 |
| 调用失败或超时 | 判为通过并说明这次没取得点评，不把人卡住；不记录未曾给出的反馈 |

**点评停在本块**：Command / Ctrl + Enter 取得判定。写得和参考一字不差（只差大小写、空格、标点）就直接进入下一块，没什么可聊。其它通过的写法（包括判定服务不可用时）停在这一块：标题标“点评”，输入框下显示对比卡片（分行，见下文“批改怎么显示”）和点评说明，同时自动开始批改讲解；聊完按 Command + Enter（`next`）：有实际改动就先做改错小测，没有就进入下一块，下一块的界面和讲解都从干净的状态开始，不再带“上一块”（2026-09-23 按使用反馈调整：点评的语音和下一块的学习分开）。没通过就留在本块，看红笔和说明（也会自动开讲这次批改）：改动文字后按 Command + Enter 重新判定；不改、直接再按一次就进入改错小测，做完按原文进入下一块（记为 `after_correction`）。检查进行中只让按钮暂停，不显示“正在检查”的状态文字。

**批改怎么显示**（2026-09-24 起，短语和整句一样）：不再在同一行里又删又加，而是分行：“你写的”一行，删掉或换掉的词标红；“改成”一行，新加的词标绿；下面每处改动一行 `from → to`，Gemini 给了原因就跟在后面。改动行来自点评结果的 `changes`（`{from, to, why}`，最多 8 条）；Gemini 没给时从两行文字的差异里本地算出，只差大小写或标点的不列。

检查进行中输入框只设为只读、不禁用：禁用会让浏览器把光标移出输入框，之后的 Command + Enter 就落空（2026-09-23 修复的“点评完要用鼠标点才能继续”）。光标不在任何输入框里时，Command + Enter 也交给当前这一块。判定只拿到这一块的中文意思、学习者写的文字和这一块的参考片段，不含整句参考，也不含其它块。

`suggestion` 是学习者原句的**最小改动版**，保留他自己的选词与语序，供前端做词级对比、划出删改；不是把他改写成参考句。

语法、词形、搭配、词义不成立才判 adjust。**只是拼写错不拦**——这是表达练习不是拼写练习，看得懂就放行，在说明末尾提一句正确拼法。拼错到认不出是哪个词属于词义问题。

**自动提示**（默认开启，开关在“更多 → 练习记录与设置”，与整句试写共用，记在本浏览器）。界面上没有提示按钮，提示分三个时机自己出现（`trigger`）：

- `start`：进入默写、框还空着，3 秒后给一个开头方向（第 1 级）。
- `pause`：输入后停笔 1 秒，针对草稿给第 1 级提示；草稿没变不重复请求，两次自动请求至少间隔 1.5 秒（2026-09-27 起；以前是 1.5 秒和 2.5 秒），输入法选字期间不计时。看过关键词之后照样给新提示，不降级。

**提示列表**（2026-09-27 起）：这一块的每一条提示都按出现的顺序留在输入框下方的列表里，最新的在最下面，列表自动滚到最新一条；正在念的那条标出来，点任意一条再听一遍。以前只显示最新的一条，打字快时新提示一来旧的就没了。列表来自练习记录里的 `phrase_hint` 事件（带这块的序号和第几遍 `run`），刷新页面也还在；紧挨着的两条一模一样的只显示一条，也只念一次。整句试写的提示也是同样的列表。
- `stuck`：一条提示出来后 10 秒草稿没动，自动给关键词（第 2 级），每块只给一次。

参考写法（第 3 级）**永远不会自动出现**；⌘ [ 仍是隐藏的手动阶梯。第 1 级的规则：

- 草稿仍是参考写法的开头：本地直接回答“到这里都对，接着往下写。”（写全了就提示按 ⌘ ↵ 检查），不调用模型。
- 其它写法：交给 Gemini（`trigger: pause`），方向对就确认并说出接下来还要表达的意思，有问题就指出问题。
- Gemini 不可用时保持安静，不反复显示预备提示。
- 每条自动提示替换对应的那一行，把 `hint_level` 提到至少它的级别，并作为 `phrase_hint` 记录（`auto: true`、`trigger`、当时草稿）。看过参考后不再自动触发。朗读跟着变了的那一行走（新的停顿提示替换第一行时，即使关键词那行还在，也会念新的第一行）。

`POST /api/sentence/phrases/hint` 的 `auto: true` 只接受 level 1–2；draft 可以为空（`start`）。

**只讲意思、用最简单的话**（2026-09-23 按使用反馈收紧）：短语提示只帮着把意思找对、把词想起来，完全不讲语法——意思对了哪怕有语法错误也当作对了，语法留给检查点评和整句；目标语言的提示只用母语国家小学低年级孩子都懂的最常用词，每句不超过 12 个词，最多两句，难的意思拆成简单的词说（sanctuary → a safe place）。提示词里带了好坏对照的例子。起初服务端还加过一道检查，把含语法术语或太长的提示拦下不显示不朗读；实际用下来提示词已经够好，按使用反馈去掉了，提示原样显示、原样朗读。按键要提示而 Gemini 不可用时，第 1 级退回一句指回屏幕上中文意思的目标语言短句，不退回预备的结构提示（那条讲的是结构）。

**提示语言**：2026-09-24 起提示**只用正在学的语言**，而且是非常简单的日常说法（像 mentor，适合听），读到、听到都是练习；网页上不再有“提示用的语言”选项。旧页面请求里带的 `hint_language` 仍会检查，但一律按 `target` 处理。本地不调用模型的固定句（“Good so far. Keep going.”等）和 Gemini 不可用时第 1 级的退路（“Look at the meaning above. Say it in easy words, one small part at a time.”，日语同样）也都是目标语言。第 1 级不能说出参考里还没写出的词（包括 if、to 这类小词），措辞不同但成立的写法直接肯定、不往参考上掰。本地“到这里都对”等固定句也按这个语言说。2026-09-23 用真实 key 抽查（当时提示还在用 `gemini-3.5-flash-lite`）：默认思考下能准确指出主谓一致、enjoy 后接 -ing、介词错误，且不泄露答案。同日起所有文字调用改用 `GEMINI_MODEL`（3.8-flash）：它的思考 token 计入输出上限，提示在 1024 上限下被截断，所以检查、提示、中文语序的上限都放到 8192；一条提示约 6 秒。

**朗读**：新出现的提示（自动或按键，第 3 级是参考写法）会被念出来。2026-09-24 起默认由 Gemini 的朗读模型念（`GEMINI_TTS_MODEL`，默认 `gemini-3.8-flash-tts`，声音 `GEMINI_TTS_VOICE` 默认 Kore）：页面把这句提示和语言（`en-US` / `ja-JP` / `zh-CN`）发给 `POST /api/sentence/speak`，本机服务带着 key 请求 Gemini 的 `interactions` 流式接口，把返回的原始音频（24 kHz、单声道、16 位 PCM）边收边转给页面，页面用 Web Audio 边收边放。语气固定为“温和耐心的老师，吐字清楚、稍慢”（按语言写）。实测（2026-09-24）第一段声音约 1.2 秒到，一条提示约 230–320 个音频 token，默认用 Flash-Lite TTS，约 $0.0015–0.002 一条（Flash TTS 贵一半，设 `GEMINI_TTS_MODEL=gemini-3.8-flash-tts` 可换回）；2027-01-01 起两者价格翻倍。每次调用记为用途“提示朗读”（`hint_speech`）；中途被新提示打断的那次拿不到用量，不计入。正在念的提示一定念完，不从半句切断（2026-09-24 按使用反馈改：以前新提示一来就打断旧的）；念的过程中又来了新提示，只留最新的一条排队、中间过时的直接丢掉（请求也取消），排队的那条一边等一边先取声音，前一条念完紧接着就念；语音陪练开讲时两条一起停。最近 40 条的声音留在页面里，重听不再请求。Gemini 没念成（没有 key、网络、额度、浏览器不让自动出声）时，这一条改用下面的系统语音念，试听那行诊断会写明原因。“更多 → 练习记录与设置”里可以改成“Mac 系统语音（不花钱）”，记在本浏览器。

系统语音由 `web/speech.js` 用浏览器的 `speechSynthesis` 念出来。在 Microsoft Edge 里优先用微软的 “Online (Natural)” 神经语音（免费，但文字经过微软的服务）；其它浏览器只用 Mac 本地语音，不用 Chrome 的网络语音。目标语言念得稍慢（0.92 倍）。含汉字的按中文读、有假名的按日语读，其余按目标语读；本地语音里优先高音质下载版，其次婷婷、Samantha 等标准语音，机械音和搞怪音效排最后。Chrome 有时会悄悄不出声（朗读对象在开始前被回收、队列卡在暂停、和取消同一瞬间发出的朗读被忽略），`web/speech.js` 对这几种都做了防护：念完前一直持有朗读对象，暂停就恢复，只在确实有声音时才取消、取消后稍等再念；2.5 秒还没开始就清空队列重试一次，仍不行就报告。“更多 → 练习记录与设置”里有“试听”按钮和一行诊断，显示最近一次是已出声（用的哪个语音）、出错（原因）还是没有开始。同一句不连续念两遍，系统语音同样念完当前这条再念最新的那条；语音陪练开着时不念；打开一块时已经在的提示不念。开关“提示出来时，用 Mac 的系统语音念出来”默认开启，记在本浏览器。

提示分三级，前两级每次求助现写，并且看得到输入框里已有的内容：

| 级别 | 来源 | 内容 |
|---|---|---|
| 1 | Gemini 现写 | 只用中文的语义方向，不出现目标语词；针对已写的内容说话 |
| 2 | Gemini 现写 | 直接给关键词/关键词组及其中文意思，一到三个；不做首字母挖空 |
| 3 | 本地 | 这一块的参考片段，零调用 |

Gemini 不可用时退回材料里预生成的提示。记录保存的是**实际显示的那句**及其来源（`gemini` / `prepared` / `reference`）。

进入一句时后台请求一次 `phrases/order`，把每块的中文按目标语语序切开重排，显示在标题处（如「培养 · 足够的内在心理余裕 · 要像无拘之舟一样」）。结果随材料缓存，每句只算一次。切分必须是原中文里**原样连续的片段**且覆盖八成以上内容，否则整条丢弃、退回原句显示——只允许重排，不允许改写。

`PHRASE_GATE=jev` 可切回旧的两层判定用于对照，该路径保留原有的自动前进行为。Jev 仍服务于逐空填空与 legacy 主题练习。

确认新材料后进入第一句第一块的学习。默写时中文意思始终显示，Command + [ 依次显示结构、开头、完整参考。Command / Ctrl + Enter 检查当前短语：已知表达本地通过，其余交给 Jev，接受保留原意的自然变体，不要求能逐字替换进固定参考。通过后自动进入下一块，最后一块完成后自动进入整句试写并聚焦输入框，不把参考或短语答案自动填成用户整句。

卡住时可以“参考后继续”。界面上没有“直接写整句”：整句只在最后一块完成后自动打开，不作为绕过短语的捷径（2026-09-23 起的 forcing function）；只有这一句拆不出短语时，才提供“拆不出短语，先写整句”。前者单独记录 reference_assisted，空白仍保持空白，不伪造回答。Jev 失败或不确定时不判错、不自动重试，可主动重试或借助参考继续。短语阶段不打百分制；整句仍由 Gemini 给分，96–100 分自动完成并进入下一句的短语阶段；下一句若已有练习进度则原样恢复。最后一句显示完成，不循环。

旧材料首次进入短语阶段时才调用 Gemini 拆解已有参考，不重新整理用户原文；拆解结果保存在 SQLite。重启不重放中断的调用。旧填空材料、接口和回答保留用于兼容，默认界面不再提供填空入口。`repeat` 保留旧轮；同轮重新练已完成的短语时保留以往短语检查历史，草稿使用新轮次键，避免旧草稿复活。

短语输入中的草稿保存在浏览器 localStorage，提交检查后也保存在 round.phrases.inputs 中。短语检查不创建整句 attempt；整句只保存用户亲自提交的完整文本。短语求助与实际表达作为支持事件进入随后整句的练习记录。CLI 的 sentence brief 包含当前短语、提示和已提交结果，便于 Codex 语音讨论；尚未提交的浏览器草稿不自动发给 Codex。

接口都沿用同源和本机认证：

- `start_phrases` 命令开始或恢复短语阶段；`practice` 可跳到整句。
- `POST /api/sentence/phrases/ensure`：`round_id, window_start, retry?`，为旧句生成一次材料。
- `POST /api/sentence/phrases/write`：另带 `index`，结束这一块的学习、开始默写；只在 `learn` 步骤可用。
- `POST /api/sentence/phrases/hint`：另带 `index, level`，level 为 1–3。
- `POST /api/sentence/phrases/check`：另带 `index, text, request_id, retry?`，异步结果通过 SSE 更新。
- `POST /api/sentence/phrases/continue`：另带 `index, text`，仅显示参考后可继续。

请求不接受客户端自定义 prompt、模型或地址。检查结果只在原 round、窗口、块序号和请求仍匹配时推进，迟到结果仅留存历史。无效材料拒绝进入练习。发送给 Gemini 的嵌套 schema 保持简单，数量和覆盖完整性由后端严格验证；官方也说明过深或过大的 schema 可能被拒绝：[结构化输出](https://ai.google.dev/gemini-api/docs/structured-output)。
## 讲解：讲解稿 + 朗读，实时语音只用来提问

2026-09-24 起，学一块之前的讲解、一块的批改讲解和整句点评的讲解，都不再由实时语音陪练自动开讲，而是：

1. 页面到了这一步（和语音陪练同一个“时刻”：`learn` / `fix` / `review`，`voiceMode(r).key`），请求 `POST /api/sentence/explain`（`round_id, window_start, key`）。
2. 服务端用 `GEMINI_MODEL`（3.8 Flash）按 `prompts/explain.txt` 写一份**讲解稿**：3–8 行，中文讲解、外语原词用外语写，学习讲解按词组逐个讲再讲语法点，批改讲解一处改动一行。讲解稿存进 SQLite 的 `explanations` 表：学习讲解按这一块的内容（语言、中文意思、参考写法、结构提示）找回，重练同一句时不再花钱；批改讲解按屏幕上的全部内容找回。
3. 讲解稿逐行显示在练习卡片最下面，同时一行一行用 Gemini TTS 念出来（`kind: explain`，语气是“中文老师讲外语，外语词用地道发音念”），正在念的那行标出来；下一行的声音在上一行播放时就开始取，接得上。可以暂停、重听；点某一行从那一行听起，点正在念的那一行就暂停或继续（不用双击：双击会选中文字，单击也得等一下看是不是双击）。标题旁可以选朗读速度 0.5×、0.75×、1×、1.25×、1.5×、2×，记在本浏览器：1× 时边收边放；其它速度每行收齐后用 `<audio>` 放，变速不变调。
   **外语读音**（2026-09-27 起）：讲解稿里每一处外语都用花括号标出，日语有汉字的带假名读音，如 `{毎日|まいにち}`、`{recently}`。屏幕上花括号不显示，外语略加粗、鼠标停上去看读音；交给 Gemini 念的是假名（中文语境里 毎日 会被念成 měirì，假名没有中文读法）；浏览器自带的声音按语言分段，中文用中文声音、外语用外语声音。旧的讲解稿会重新写一遍（缓存键加了 `v2`）。实时语音陪练的说明里也加了：日语汉字词一律按日语读。
   **朗读分工**（2026-09-28 起）：「服务与 key」里的朗读有三种：讲解用 Gemini、提示用浏览器自带（`SPEECH_PROVIDER=mixed`，有 Gemini key 时的默认）；都用 Gemini（`gemini`）；都用浏览器自带（`browser`）。提示又多又短，最容易把 Gemini 朗读的次数用完。**两个朗读模型轮换**：`gemini-3.8-flash-lite-tts` 和 `gemini-3.8-flash-tts` 各有自己的额度（Tier 1 各是每分钟 10 次、每天 100 次，2026-09-27 在 AI Studio 的 Rate Limit 页看到；Tier 2 各是每分钟 1000 次、每天 1 万次），一个被拒就马上换另一个念，两个都被拒才改用浏览器自带的声音；被拒的模型在它说的恢复时间之前不再请求。
   **用量在工具栏上**（插件版）：一句的图标上显示今天大约花了多少，鼠标停上去看今天调用次数、DeepSeek/千问的次数（不估金额）和两个朗读模型在 Google 这一天里各念了几次；一个模型用完图标变橙，两个都用完变红。「模型花费」里也有同样的朗读次数。Google 的一天从太平洋时间零点算起（北京时间下午 3 点，冬令时 4 点）。
   **Gemini 朗读额度**：朗读模型的额度很小（2026-09-27 遇到 Tier 1 每天 100 次的上限，每行讲解、每条提示各算一次）。被拒绝时，讲解和提示改用浏览器自带的声音念，并写明原因（“Gemini 朗读今天的 100 次用完了，约 N 小时后恢复”）；在它说的恢复时间之前不再去请求。
4. 学一块时，下一块的讲解稿在后台先写好，到了下一块几乎立刻开始念（实测 0.1 秒显示、约 1 秒出声）。
5. 听过讲解稿记一条 `explanation` 支持事件（时刻、行、是否取自存档）；学习讲解同时记 `learn.explained`，默写前听过讲解就算学过（`skipped: false`），不必再开实时语音。

**实时语音只手动打开**（⌘ ] 或“问问题 · ⌘ ]”）。打开时，陪练的上下文里带着“已经念过的讲解稿”，开场只用一句中文问你想问哪里，不重讲；你要它再讲某部分时才讲。设置“进入每一块、看到批改时，自动念讲解”控制的是讲解稿朗读。

**花费对比**（2026-09-24 实测）：一块学习讲解 = 讲解稿约 $0.001 + 三行朗读约 $0.005（Flash-Lite TTS），合计约 $0.006；原来实时语音自动讲一段约 $0.013–0.017。按每秒声音算，TTS 和 Live 差不多贵；省下来的主要是：讲解稿和声音都能存下来重放、追问时不再把前面的独白声音重复计费、Flash-Lite 便宜三分之一。

**朗读存档**：所有朗读（提示和讲解）按“模型、声音、语气、文字”存成 `studio/data/tts-cache/*.pcm`，同样的话再念直接从磁盘读，不花钱（诊断里显示“已存，不花钱”）；只存完整念完的，超过 300 MB 删最旧的。

`GEMINI_TTS_MODEL` 默认改为 `gemini-3.8-flash-lite-tts`（提示和讲解都用）。用量里新增：讲解稿（学习）`explain_learn`、讲解稿（批改）`explain_fix`、讲解朗读 `explain_speech`。

## 语音陪练面板

**讲解语言**：陪练（学习讲解、批改讲解、试写陪练）一律用中文讲解，外语的词、词组、例句用外语原样说，他用外语提问也用中文答，除非他明确要外语——实时对话用母语最省力。提示则相反，只用外语，练听力。这条规则写进了每一种讲解的提示词，开讲那句话里也再提一次：2026-09-23 的 42 段录音里有 1 段整段滑成了英语。

面板顶上始终回答两件事：现在是哪一部分（如“短语 2 / 4 · 讲解”“短语 1 · 批改讲解”“整句 · 点评讲解”），陪练在做什么（正在连接… / 陪练准备开讲… / 陪练在讲 / 在听，你可以提问，带用时和花费；没开时是“还没开始讲这一块”和“开始 · ⌘ ]”）。下面只列**这一部分**的对话；同一句里别的块、别的讲解折叠在“这一句的其它对话”里，点开可以重读。上一段为什么结束（如“这一块学完了”）只留在上一段，进入新的一块时顶上的状态清空。讲解范围和花费说明折叠在“陪练看得到什么、花费怎么算”里。

**同一个练习开在两个窗口时**（比如 Chrome 和 Edge 各开一个，或同一浏览器两个标签页）：以前两边进入新的一块都会自动开讲，后开的把先开的挤掉，被挤掉的那边只剩一句“新的语音开始了，上一段已结束。用时 0:00”（2026-09-24 从记录里看到每一块都有一段 0 秒的会话）。现在页面自己开的讲解（`auto=1`）遇到另一个窗口已经在讲同一处，就不开，并说明“已经在另一个窗口里开着了，要在这里听按 ⌘ ]”；手动 ⌘ ] 仍然接管。被接管的一边显示“另一个窗口开始了语音，这里的这段已结束。”没接通的会话不再显示“用时 0:00 · 实际花费 $0”。每次打开页面都有自己的编号（`page`），页面自己前一段还没挂断的会话不会把它挡在外面。打开着的练习页面之间用 `BroadcastChannel` 互相报到，同一个浏览器里开了不止一个时，面板顶上写“这个练习还开在另外 N 个标签页或窗口里……只留一个就好”；关掉多余的那个，十几秒内提示消失。（不同浏览器之间看不到彼此。）

**页面有更新**：服务启动时算出网页代码的指纹（`build`），通过 `/api/sentence/events` 第一条事件发给页面。服务重启后页面自动重连，收到的指纹和自己加载时不同，顶栏就出现“页面有更新 · 点这里刷新”。2026-09-24 的教训：服务换成 Gemini 朗读后，没刷新的页面还在跑旧代码、用系统语音，在 Chrome 里一声不出，看起来就像新功能坏了。

## 改错小测与 Anki

批改讲完之后，按 Command + Enter 不直接往下走，而是先做一道**改错小测**：把改过的那句拿出来，每处真正改过的词挖成空（只差大小写或标点的不挖），上面写着中文意思，凭记忆填回去。短语（批改后的写法；没通过又没改时用参考片段）和整句（点评的 `suggestion`）都有，整句在“完成本句”时进入，做完才算完成（`complete` 在小测没做完时返回 409）。

- 输入框嵌在句子里，Enter 跳到下一空，Command + Enter 检查。
- 和批改写的一样（忽略大小写和首尾标点）：本地判对，不调用模型。其它答案一次交给 `GEMINI_MODEL`（`prompts/quiz-check.txt`，用途 `quiz_check`）：同义词、另一种正确形式也算对，只错一两个字母算对但会写出正确拼法；不对时给一句中文说明，不直接写出答案。Gemini 不可用时不一样的写法算没填对。
- 全对立刻进入下一块 / 完成本句。没全对再试一次：对的空锁住，错的空保留原文并选中，直接打字覆盖。第二次还没全对，答案写在错的空旁边，看一眼按 Command + Enter 继续。
- 小测记在 `inputs[i].quiz`（短语，`phrases.step` 为 `quiz`）或 `round.quiz`（整句）里；每次作答另记一条 `quiz` 支持事件（答案、正确答案、每空对错）。小测期间不开语音陪练。

接口：`POST /api/sentence/quiz/answer`（`round_id, quiz_id, answers`）和 `POST /api/sentence/quiz/continue`（`round_id, quiz_id`，只在两次都没全对、答案已显示后可用）。

**每道小测同时变成一张 Anki 填空卡**，出小测时就放进本地 SQLite 的 `anki_outbox`，再通过 AnkiConnect 推到牌组 `一句::改错`（`ANKI_DECK`）。卡片正面是那句话，改过的词是 `{{c1::…}}` 空，复习时要打字填（`{{type:cloze:Text}}`，和练习时一样）；背面附中文意思、当时写的原文和每处 `from → to：原因`。标签：`一句`、`英语`/`日语`、`短语`/`整句`。

- 用自己的笔记类型 `一句 · 改错填空`（字段 Text、Extra），第一次推送时自动建好，不碰已有的笔记类型（这台 Anki 里没有内置的 Cloze，只有别的自定义模板）。
- Anki 没开时卡片留在待推送里，服务启动时和之后每 5 分钟重试，也可以在“更多 → 练习记录与设置 → Anki”手动“现在推送”；那里显示已推送、待推送、失败的张数和最近的错误。Anki 里已经有的卡算已推送。
- 只有真正的练习服务（`server/main.mjs` 的 `ankiPush: true`）会推送；测试和预览只放进 outbox，不碰真的 Anki。
- 地址 `ANKI_CONNECT_URL`，默认 `http://127.0.0.1:8765`（AnkiConnect 的标准端口），只允许本机。8765 被别的程序占用时，可以在 AnkiConnect（Anki 附加组件 2055492159）的配置里改 `webBindPort`，再把这里的地址改成同一个端口（也可以在「服务与 key」的「AnkiConnect 地址」里改，插件版只能在那里改）；改端口后要重启 Anki。
- `GET /api/anki` 返回状态，`POST /api/anki/flush` 立即推一次。
